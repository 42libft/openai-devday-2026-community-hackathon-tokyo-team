# 発表の相棒：手動デモの操作と受入条件

この手順は、カメラやマイクを開始せずにサンプル台本と状態復元を試すものです。自分の台本は開始前の「自分の台本を編集」から保存できます。
現行版にはDecisions APIによるカメラ判定と、ブラウザの音声認識も接続されています。
その開始条件と検証範囲は [README](../README.md)、[ジェスチャー検証](gesture-evidence.md)、[音声の仕様](voice-input.md) を参照してください。
この手順の検索は同梱の架空データだけを使い、検索語や結果を外部へ送りません。

## 90秒のデモ

1. **準備**：3工程の台本を確認して開始する。「発表中に質問が来ると、元のスライドとデモの状態を探し直すことがあります。」
2. **進行**：「次へ」で2工程目へ進む。「取り消し」で戻れることを見せ、再び2工程目へ。
3. **デモの状態を作る**：検索し、結果を1件選択する。検索語と選択した項目を観客に見せる。
4. **質問に対応する**：別の工程を選ぶ。候補が出てもまだ移動しないことを確認し、「移動する」で確定する。
5. **寄り道中に変更する**：別の語で検索し、選択も変える。必要なら隣の工程へ進む。
6. **続きに戻る**：「続きへ戻る」で、元の工程・検索語・結果・選択が一緒に戻ることを示す。「探し直さず、説明の続きに戻れます。」
7. **限界を伝える**：「いま見せたのはボタンによる状態復元です。カメラはDecisions、音声はブラウザの認識機能に接続していますが、実センサーの精度や発表時間の短縮はまだ測っていません。」

## 操作

| 操作 | ボタンまたは入力 |
|---|---|
| 開始 | 台本を確認して開始、または「準備する」 |
| 隣接工程 | 次へ／前へ、左右矢印またはPageDown／PageUp |
| 直前の1操作の取消し | 取消し、またはU |
| 別の工程を候補にする | 工程のボタン、または「1枚目へ」等 |
| 候補を確定／破棄 | 移動する／キャンセル |
| 寄り道前へ復帰 | 続きへ戻る、またはR。文字・音声の定型句は「続きへ」 |
| 検索 | 検索欄、または「検索 キーワード」 |
| 停止／新しく準備 | 発表欄の「停止」／「はじめから」→開始 |

入力欄の操作中はキーボードで工程を動かしません。文字入力は正規化した定型句の完全一致だけです。一般の文章の意味は推定しません。空の検索欄で検索すると全件を表示します。
音声の「3枚目へ」と「確認」は分けて発話します。音声の呼びかけ・句読点対応は文字入力とは別の処理です。
カメラ欄の「停止」はカメラだけ、「音声を停止」は音声だけを止めます。発表欄または発話の「停止」は発表と両入力を止めます。

## 状態の約束

- 寄り道前の保存は1段だけ。寄り道中に検索や選択、隣接工程を変更しても戻り先を上書きしません。
- 「前へ」は隣の工程への移動。「取消し」は直前1操作の取り消し。「続きへ」は寄り道前の全対象の復元です。
- 検索・結果選択も取消し対象です。取消しを2回押して往復する動作はありません。
- 候補提示だけでは移動しません。候補の後の新しい確認で確定します。
- 古い版、前セッション、重複した入力は適用しません。停止後は再開操作まで状態を変えません。
- 保存対象は、このタブの工程・検索語・結果ID・選択IDです。外部アプリ・通信処理・ブラウザ再読み込み後の復元は含みません。

## 実装の入口

- `src/state/presentation.js`：3工程、架空検索データ、状態遷移と復帰。
- `src/input/manual.js`：定型句・キーボード、版付きの手動イベント。
- `src/ui/view.js`：画面表示と操作通知。
- `src/controller.js` / `src/main.js`：状態の一元管理と接続。
- `test/`：状態、入力、統合、開発／ビルド出力のHTTP検査。

## 未実施・対象外

実カメラ・実マイクでの認識精度と遅延、Markdownからの台本生成、PowerPoint取込、任意の外部アプリ操作、複数段の寄り道、利用者による便益の実測は未確認または対象外です。
公開版と実Decisions APIへの接続の記録は [ジェスチャー検証](gesture-evidence.md) にあります。
この手動デモの成功は、実カメラ・実音声の認識や正式採点・提出の完了を意味しません。
