# スライドだけの投影表示（Issue #34）

更新: 2026-10-18。単一タブでの投影表示。別ウィンドウ・外部アプリの画面共有は含まない。

## 使い方

1. 開始前にPDF/PPTXを読み込み、先頭ページを確認して発表を開始する。[ファイルの手順](slide-upload.md)
2. 「スライドを全画面表示」を押す。ブラウザの全画面化はこの明示操作時だけ要求する。「スライドのみ表示」はブラウザの全画面機能を使わず、タブ内をスライド専用にする。
3. 左右矢印、PageUp/PageDown、音声・カメラで進める。音声の「8枚目へ」→「確認」、寄り道後の「続きへ」も同じ状態処理を使う。
4. Esc、ブラウザの全画面終了操作、または「操作画面へ戻る」で戻る。現在ページ・寄り道の戻り先・検索/選択・入力モードを表示切替によって変更しない。
5. 操作ボタンは下端にポインタを置くかTabで表示する。「手動に切り替え」で音声・カメラを停止し、発表を継続できる。「発表を終了」は投影を閉じ、入力も終了する。

投影対象は読み込んだスライドの描画領域だけ。発表者ノート、台本文、設定、文字起こし、診断値は含めない。操作時には最小限の操作バーと寄り道の確認を重ねる。ファイル未読込のサンプルでは工程のタイトルだけを投影する。

## 失敗時と制限

- 全画面が非対応・拒否されたら通常画面へ戻し案内を表示する。「スライドのみ表示」と手動操作は継続できる。タブが背景の場合などにもブラウザが拒否するため、前面で操作する。
- 全画面終了に失敗した場合は投影内の操作を保持し、Esc/ブラウザからの終了を案内する。遅れて成功した古い開始要求は閉じる。
- スライドの縦横比を保持し、余白を黒くする。PPTXの再現性・ファイル上限は読み込み機能と同じ。
- 入力開始/停止は既存の同意とライフサイクルを使う。他タブへの移動など、既存の入力停止条件は引き続き適用する。
- 同じタブなので、台本を手元に表示しながら投影だけ別画面へ出す発表者ビューではない。

## 実装

- `src/projection/controller.js`: 表示とFullscreen APIのライフサイクル。発表のreducerや入力所有権を変更しない。
- `src/ui/projection.js`: 同じスライドDOMを専用領域へ移して復帰。通常UIをinertにし、終了時にフォーカス・スクロールを復元する。
- `src/projection.css`、`src/slides/deck.js`、`src/slides/upload.js`: ページごとの縦横比を描画領域へ反映する。
- `test/projection.test.mjs`: 非対応・拒否、ブラウザ終了、遅延完了、終了失敗、状態保持と進行を確認する。

Fullscreen APIの開始要求はユーザー操作から直接実行し、`fullscreenchange`でブラウザ側の終了も扱う。[WHATWG仕様](https://fullscreen.spec.whatwg.org/)

## 2026-10-18の検証

Node.js 24.19.0 / macOS arm64。`npm test`（ビルドと108件）が成功。

Chromeの配布用ビルドで次を確認した。音声認識・カメラ映像・判定APIのみ模擬。スライド読込/描画、画面操作、ネイティブ全画面は実ブラウザの機能を使用し、実認識精度やAPI品質の検証とは区別する。

| 確認 | 結果 |
|---|---|
| 発表者ノート付き8枚PPTX | 全画面表示成功。ノートに入れた識別文字列は投影領域に存在せず、台本・設定・診断値も投影されない |
| 進行・寄り道 | 矢印で前進。模擬音声で2枚目→8枚目の確認付き移動→2枚目復帰。模擬カメラNEXTで2→3枚目 |
| Escによる全画面終了 | 8枚目・2枚目への戻り先・音声聞き取り中を保持。別経路では3枚目とカメラ操作中を保持 |
| 操作・終了 | Tabで操作画面へ戻るボタンへ到達。手動切替で両入力停止。投影内の発表終了で通常画面へ戻り停止中 |
| 画面比率 | 縦長PDFを横長画面と390×844で確認。上下左右4隅の目印が見え、切れない |
| 拒否・非対応 | ローカル検証ページで拒否/非対応を模擬し、通常画面と案内、スライド専用表示からの復帰を確認 |

再現用のローカル検証ページはビルド後に `node scripts/projection-browser-fixture.mjs` で生成する。任意の `PROJECTION_PPTX` / `PROJECTION_PDF` にローカル資料を指定すると、検証専用の読込ボタンから実際のファイル入力・描画処理を通せる。`npm run preview` で `/_projection-check.html`、`/_projection-denied.html`、`/_projection-unsupported.html` を開く。模擬音声/カメラのキーは各ページの帯に表示する。

この検証ページはローカル専用。配備前には再度 `npm run build` を実行し、`dist/_projection-*` を含めない。公開環境・全ブラウザ・実マイク/カメラは今回未検証。

確認画像: [PPTX全画面](evidence/projection-20261018/pptx-fullscreen.png)、[縦長PDF・390px幅](evidence/projection-20261018/portrait-on-narrow.png)。

## 公開版にボタンがない場合の確認

2026-10-18 17:50 JSTの追加確認では、main `1f3f4a0` の配布用ビルドはChromeの実クリックでネイティブ全画面に入った。一方、公開URLのエントリーJavaScript `index-DG8BkAnM.js` には全画面ボタン・投影領域・Fullscreen APIの呼出しが含まれていなかった。公開版への未反映と、ブラウザによる全画面拒否は区別して確認する。

ビルド後、実際のHTMLが参照しているJavaScriptとCSSを検査できる。

```sh
npm run build
node scripts/check-projection-release.mjs
# ローカルpreviewでも、同じHTMLから配布資産を確認する
node scripts/check-projection-release.mjs http://127.0.0.1:4173/
```

採点・予選終了後にPRを取り込んだら、全画面機能を含む検証済みビルドを公開担当が反映し、その後に確認する。マージ成功だけを公開反映の証拠にはしない。

```sh
node scripts/check-projection-release.mjs https://devday-presentation-companion.vercel.app/
```

全項目が`true`になった後、新しくページを開いて発表開始→「スライドを全画面表示」→Escで戻ることを確認する。この検査は公開資産の読取りだけで、配備・認証・実センサー・判定API呼出しは行わない。資産に機能が含まれていても、端末・ブラウザの全画面対応や権限まで保証するものではない。
