# 声で発表を進める

公開URLの「同意して音声を開始」でブラウザのマイク許可を受け、操作する言葉だけを短く話す。開始前にはマイクも認識サービスも起動しない。準備前なら発表も同時に開始する。

| 発話 | 動作 |
|---|---|
| 次へ／前へ | 工程を1つ進める／戻す |
| 取り消し | 直前の操作を1回戻す |
| 1枚目へ／2枚目へ／3枚目へ → 確認 | 候補を出して確認後に寄り道する |
| キャンセル | 寄り道の候補を取り下げる |
| 続きへ | 寄り道前の工程・検索語・結果・選択に復帰する |
| 停止 | 発表・音声・カメラを停止する |

「相棒、次へ」のような呼びかけ、末尾の句読点にも対応する。説明文「次へと言います」や否定文は操作しない。音声での検索・開始・リセットは対象外。「音声を停止」ボタンは音声入力だけを止める。別タブに移ると音声とカメラを止め、戻っても自動再開しない。

## 実装とデータの扱い

`src/input/speech.js` が `SpeechRecognition` / `webkitSpeechRecognition` の日本語認識を使い、確定した文字を限定されたコマンドへ変換する。`src/main.js` → `src/state/presentation.js` の既存状態処理へ `source: voice` のイベントを渡す。`src/ui/speech-panel.js` が状態と聞き取った言葉を表示する。

- 途中の認識結果は画面表示だけ。同じ認識結果の再送と短時間の同一操作を抑える。
- 発話開始時のセッションと版を捕捉し、途中で画面が変わった場合は実行せず再発話を案内する。
- 1発話につき最初の未処理の確定結果だけを判定する。採用・拒否後は新しい `speechstart` まで再受付せず、同じ結果イベントの残りも実行しない。「3枚目へ」と「確認」は分けて話す。発話開始イベントより先に届いた結果も実行しない。
- 停止・終了・認識エラー・再開始の後に届いた古い結果は実行しない。ブラウザによる終了時は終了を表示し、再開は本人のボタン操作で行う。
- カメラ判定はOpenAI Decisions API。音声認識はブラウザ提供元の機能であり、このアプリのOpenAIキーを使わない。音声が提供元の認識サービスへ送られる場合がある。アプリは音声を保存せず、認識文字は表示用メモリにのみ保持する。
- 非対応、マイク拒否、機器なし、ネットワーク不良、無音、日本語非対応を案内し、文字入力・ボタンを残す。日本語パックは自動インストールしない。

ブラウザ対応・ネットワーク要件は [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、停止の意味は [abort()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/abort) を参照。

## 検証

2026-10-18、`npm test` の全68件に、音声の正規化・途中結果・重複・古い版・停止後応答・拒否／ネットワーク失敗・非対応・寄り道復帰を含め成功。

実ブラウザでは模擬認識器と実UIを接続し、PCと狭い画面で計17状態を確認した。開始、確定NEXT/PREVIOUS、途中結果、重複、説明文、取消し、音声停止、発表停止、遅い結果、マイク拒否、再開、ブラウザによる終了、非対応を含む。コンソールエラー0。モバイル要求幅390pxに対する実測layout幅433pxで横溢れ0。

再現準備は `npm run build && node scripts/speech-browser-fixture.mjs`、プレビューの `/_speech-check.html` と `/_speech-unsupported.html`。生成ページは検証専用で、配備ファイルに含めない。実マイクや認識サービスへの通信は使わない。

**未検証**：本人の実マイク、各ブラウザの実認識サービス、会場の雑音・発音・ネットワークによる精度と遅延。模擬入力の成功を音声認識精度と扱わない。
