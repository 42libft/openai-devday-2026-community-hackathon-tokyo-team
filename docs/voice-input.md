# 声で発表を進める

公開URLの「同意して音声を開始」でブラウザのマイク許可を受け、操作する言葉だけを短く話す。開始前にはマイクも認識サービスも起動しない。準備前なら発表も同時に開始する。

| 発話 | 動作 |
|---|---|
| 次へ／前へ | 工程を1つ進める／戻す |
| 取り消し | 直前の操作を1回戻す |
| N枚目へ → 確認 | 読み込んだページ数の範囲で候補を出し、確認後に寄り道する（最大100枚） |
| キャンセル | 寄り道の候補を取り下げる |
| 続きへ | 寄り道前の工程・検索語・結果・選択に復帰する |
| 停止 | 発表・音声・カメラを停止する |

「相棒、次へ」のような呼びかけ、末尾の句読点にも対応する。説明文「次へと言います」や否定文は操作しない。音声での検索・開始・リセットは対象外。「音声を停止」ボタンは音声入力だけを止める。別タブに移ると音声とカメラを止め、戻っても自動再開しない。

## 実装とデータの扱い

`src/input/speech.js` が `SpeechRecognition` / `webkitSpeechRecognition` の日本語認識を使い、確定した文字を限定されたコマンドへ変換する。`src/main.js` → `src/state/presentation.js` の既存状態処理へ `source: voice` のイベントを渡す。`src/ui/speech-panel.js` が状態と聞き取った言葉を表示する。

- 途中の認識結果は画面表示だけ。同じ認識結果の再送を拒否する。別の認識器で受け付けた同じ操作は短時間でも実行できる。
- コマンド1つにつき認識器を区切り（`continuous=false`）、開始時の発表セッションと版を固定する。途中で画面が変わった結果は実行しない。「停止」は同じ発表セッションなら版が変わっても受け付ける。
- 認識器ごとに最初の確定結果だけを判定する。確定結果または不一致の後に認識器が終了したときは、新しい認識器で次の操作を待つ。各コマンドの前の`speechstart`を前提にしない。「3枚目へ」と「確認」は別の認識区間に分ける。
- 最初の発話開始は固定済みの版を更新しない。確定前に2回目の発話開始が届いた場合は対応を特定できないため停止する。
- 無音の待機には6秒の制限をかけない。最初の発話開始、または発話開始イベントがない場合は最初の空でない途中結果から、6秒の確定待ち上限を設ける。後続の途中結果では期限を延ばさない。期限を超えた認識区間を破棄し、古い結果を拒否して次の操作を待つ。
- 確定結果がないままブラウザが認識を終了した場合、`no-speech`、確定待ち超過では、認識器を入れ替えて待機を続ける。連続した空の認識区間には250msから最大2秒の待機を挟み、再開始のループを抑える。
- 明示停止・発表終了・タブ離脱・カメラへの切り替えは再開始の予約も取り消す。権限・機器・通信エラーや重複した発話開始は従来どおり停止し、本人のボタン操作で再開する。停止・破棄・再開始の後に届いた古い結果や終了通知、古いタイマーは新しい入力を操作しない。
- カメラ判定はOpenAI Decisions API。音声認識はブラウザ提供元の機能であり、このアプリのOpenAIキーを使わない。音声が提供元の認識サービスへ送られる場合がある。アプリは音声を保存せず、認識文字は表示用メモリにのみ保持する。
- 非対応、マイク拒否、機器なし、ネットワーク不良、無音、日本語非対応を案内し、文字入力・ボタンを残す。日本語パックは自動インストールしない。

ブラウザ対応・ネットワーク要件は [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、停止の意味は [abort()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/abort) を参照。

## 検証

### Issue #35：無音待機と発話の確定待ちを分離

2026-10-18、Node.js v25.6.0で `npm test` はビルド・開発/静的HTTP検査を含む118件が成功。最新mainの入力状態表示・固定操作バー・音声非対応表示を取り込んで確認した。無音で60秒待った後と操作成功後の受付、`no-speech` と空の終了からの再受付、途中結果だけの場合の6秒期限、期限切れの古い結果の拒否、再開始の待機間隔、停止・発表終了・セッション変更・タブ離脱による再開始予約の取消しを確認した。

ローカルの `/_speech-check.html` に模擬認識器を接続した実ブラウザでも、開始後約10秒の無音→次へ、操作後約14秒の無音→前へ、未確定の発話を6秒以上放置→古い確定結果の拒否→新しい次への受付、`no-speech` 後の受付、手動切り替えと権限エラー後の古い結果の拒否、明示再開を確認した。実マイク・実認識サービスは使っていない。

再現手順は `node scripts/speech-browser-fixture.mjs` で生成したページの「途中の次へ」→6秒以上待機→「期限切れの確定結果」（移動しない）→「次へ確定」（移動する）。「無音通知」と「ブラウザ終了」からも待機を続け、「手動に切り替え」または権限エラー後は自動で再開しない。生成ページは検証専用で、配備対象に含めない。
