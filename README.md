# 発表の相棒

**質問で寄り道しても、元の工程とデモの状態へ戻れる発表支援ツール。**
質問への対応後に、工程・検索語・検索結果・選択中の資料をまとめて復元します。

3工程の台本と架空の4資料を使います。カメラ画像を **Decisions API** でNEXT／PREVIOUS／NONEへ判定し、音声・手動操作も接続しています。

[公開デモを開く](https://devday-presentation-companion.vercel.app/)

手・声・ボタンで進行します。公開APIは合成白画像でHTTP 200・NONEを確認済み。実カメラ・マイクの認識精度は未検証です。

カメラと音声は切り替えて使います。音声を開始するとカメラと画像送信が停止し、カメラを開始すると音声が停止します。ボタン・文字入力はどちらのモードでも使えます。

開始前に「自分の台本を編集」→「台本を保存して反映」。3工程のタイトル・本文を変更でき、再読込後も同じブラウザに残ります。再編集は停止→「はじめから」。

## カメラで使う

HTTPSの公開URLで「同意してカメラを開始」を押し許可すると、発表が始まり、約2秒の間隔を空けて静止画をOpenAIへ送ります。マイクは音声入力の開始時だけ使います。

1. 片手を開いて映します。判定が確定すると次の工程へ進み、判定・確信度・待ち時間を表示します。
2. 一度手を画面から下ろして「次の合図を出せます」を待ち、握り拳を映すと前へ戻ります。
3. 誤操作は「取り消し」で戻せます。「カメラを停止」でカメラ・送信を終了し、同じ発表中にカメラを再開できます。「発表を終了」は音声も含めて終了し、再開には「はじめから」での再準備が必要です。別タブへ移っても入力は停止します。

同じ手の保持・低確信度・古い返答・重複・無効な出力では動きません。通信失敗は停止し復旧方法を表示します。権限を拒否した場合は設定を確認して再開し、利用上限時は1分待ちます。

APIキーはサーバーの `OPENAI_API_KEY` だけに設定し、クライアントには渡しません。画像はこのアプリのログ・ファイルに保存しません。実装の接続は後述の表で追えます。

## 声で使う

「同意して音声を開始」でマイクを許可し、「次へ」「前へ」「取り消し」「続きへ」を話します。「停止」は発表・音声・カメラを停止します。「3枚目へ」→「確認」で寄り道もできます。ブラウザの音声認識を使用し、音声が提供元のサービスへ送られる場合があります。非対応時は文字入力を使えます。終了した場合は明示的に再開します。[音声の仕様と検証](docs/voice-input.md)

## まず試す流れ

1. 「台本を確認して開始」を押し、「次へ」で2工程目「検索デモを見せる」へ進みます。
2. 「資料を探す」で **写真** を検索し、結果の **まちの色ギャラリー** を選びます。
3. 上部の3工程目「発表をまとめる」を押します。候補の確認が表示され、この時点では現在の工程は変わりません。
4. 「移動する」を押して寄り道します。寄り道先で **ノート** を検索し、**読書メモ** を選びます。
5. 「続きへ戻る」を押します。2工程目・検索語「写真」・検索結果「まちの色ギャラリー」・その選択が一緒に戻ります。

| 場面 | 工程 | 検索語 | 検索結果 | 選択中の資料 |
|---|---|---|---|---|
| 寄り道する前 | 検索デモを見せる | 写真 | まちの色ギャラリー | まちの色ギャラリー |
| 寄り道中に変更 | 発表をまとめる | ノート | チームのアイデア帳、読書メモ | 読書メモ |
| 続きへ戻った後 | 検索デモを見せる | 写真 | まちの色ギャラリー | まちの色ギャラリー |

復元の検証は `test/state.test.mjs`、手動の手順は [操作ガイド](docs/mvp-demo.md) にあります。

## ローカルで起動する

Node.js 24以降とnpmが必要です。
取得済みの場合は `npm ci` から実行してください。

```sh
git clone --branch work/mvp-presenter-20261018 https://github.com/42libft/openai-devday-2026-community-hackathon-tokyo-team.git
cd openai-devday-2026-community-hackathon-tokyo-team
npm ci
npm run dev
```

`http://127.0.0.1:5173` を開きます。
手動操作、検索と状態復元はAPIキーやカメラなしで使えます。カメラのAI判定には、管理者が `.env.local` に `OPENAI_API_KEY` を設定しサーバーを起動します。`.env.example` を参照してください。環境変数を `VITE_` で始めたり、キーをGitへ追加したりしないでください。Viteの開発・previewサーバーでも同じAPI処理を利用します。

## 操作と、困ったときの戻り方

| 操作 | 使い方・復旧 |
|---|---|
| 工程を前後へ動かす | 「次へ」「前へ」、左右矢印、PageDown / PageUp。最初・最後ではそれ以上進みません。 |
| 直前の操作を戻す | 「取り消し」、U。進行・検索・選択など直前の1操作だけを取り消します。 |
| 寄り道する・戻る | 上部の工程 →「移動する」。候補をやめるなら「キャンセル」かEscape。復帰は「続きへ戻る」、R、または定型句「続きへ」。 |
| 検索・選択 | 架空の資料名・説明を部分一致検索。空欄は全4件、上限120文字。0件なら語を変えるか空欄で再検索できます。 |
| 文字で操作 | 「次へ」「取り消し」「1枚目へ」等の定型句。未対応文では移動せず案内を表示します。入力上限180文字。 |
| 止める・新しく始める | 「発表を終了」または発話の「停止」で発表・カメラ・音声を停止。「はじめから」→開始で新しい発表を準備します。「カメラを停止」と「音声を停止」はそれぞれの入力だけを止めます。 |

文字入力中・日本語変換中は工程のショートカットを抑止します。
候補提示後に状態が変わると、古い確認は適用しません。
カメラ・音声が使えない場合も、ボタンで検索・寄り道・復帰を試せます。

## 工程と検索を一緒に戻す仕組み

単に「前へ」で工程を戻しても、寄り道中に変えた検索語や選択は元に戻りません。
本アプリは寄り道の確定時に次の4項目をまとめて保存します。

```text
工程 + 検索語 + 検索結果IDの配列 + 選択中の資料ID
```

「続きへ戻る」はこの4項目を一度に復元します。
寄り道中の検索・選択・隣接工程への移動では戻り先を上書きしません。
保存できる戻り先は1段です。

入力にはイベントID、セッション番号、状態の版を付け、同じ入力の再送、古い状態への操作、前のセッションから届いた操作を状態処理で拒否します。
取消し用の履歴と寄り道の戻り先を分けることで、寄り道中の操作を取り消しても元の戻り先を保持します。

## Decisions APIを選んだ理由

カメラから受け取りたいのは「次へ・前へ・操作なし」の3択です。
`api/decide.js` は [Decisions API](https://developers.openai.com/api/docs/guides/decisions) の画像入力とchoice質問を使い、`gpt-6-luna` にこの3択を渡します。
confidenceと選択肢の確率がともに0.9以上の場合だけ操作候補を通し、曖昧な画像や不正出力では進みません。
実呼出しは `POST https://api.openai.com/v1/decisions` です。

## 連続操作を抑える仕組みの検証

同じ手を出し続けたときに何度も進まないよう、操作後は手を下ろした判定（確実なNONE）が来るまで次の操作を待ちます。
合成済みの5判定 `NEXT, NEXT, NONE, PREVIOUS, PREVIOUS` を本番の状態処理へ渡した再現テストでは、毎回実行する方式の4回に対し、本方式は2回だけ移動し、保持中の余分な移動を抑えました。

再現は `node scripts/gesture-comparison.mjs`。根拠は [比較結果JSON](docs/gesture-comparison.json) と [検証手順](docs/gesture-evidence.md) にあります。
この検証の対象は連続操作の抑止です。実画像での認識精度・API遅延・発表時間の短縮は未測定です。

## 適用範囲と制約

- 3工程のタイトル・本文は編集・ブラウザ保存可。資料4件は架空データです。PowerPoint取込、台本生成、外部アプリ操作は対象外です。
- 復元はこのタブ内の工程・検索・選択だけ。戻り先は1段、取消しは1操作です。再読み込みで初期化され、別端末・別タブへの同期はありません。
- カメラの約2秒は判定後の待機間隔です。即応性は端末・回線・認識サービスに依存します。閾値0.9は認識精度90%を保証せず、照明・背景・遮蔽にも影響されます。
- レート制限はAPIインスタンス単位です。複数インスタンスを横断する厳密な課金上限ではありません。
- 実カメラ・実マイクの精度、発表現場での使いやすさ、時間短縮や負担軽減の量は未測定です。
