# 発表の相棒

PDF・PowerPoint（PPTX）を読み込み、声・手の合図・ボタンで進行する発表支援ツールです。質問で別のページへ寄り道しても、元のページへ戻って発表を続けられます。

| 操作方法 | 必要なもの | できること |
|---|---|---|
| 手動 | APIキー・カメラ・マイクは不要 | ボタン・キーボードで進行、寄り道と復帰を操作 |
| カメラ | カメラとサーバーのOpenAI APIキー設定 | 画像をDecisions APIで判定し、開いた手で次へ、握り拳で前へ移動 |
| 音声 | マイクとブラウザの音声認識機能。OpenAI APIキーは不要 | 「次へ」「取り消し」などの定型句で進行、寄り道と復帰を操作 |

[公開デモを開く](https://devday-presentation-companion.vercel.app/)

既存の検証記録では公開カメラAPIに合成白画像を送り、HTTP 200・NONEを確認しています。実カメラ・実マイクの認識精度は未検証です。

カメラと音声は切り替えて使います。音声を開始するとカメラと画像送信が停止し、カメラを開始すると音声が停止します。ボタン・キーボードはどちらのモードでも使えます。

## 自分のスライドで発表する

開始前の「スライドファイル」でPDF／PPTXを選択し、先頭ページと枚数を確認して発表を開始します。25MB・1〜100ページまで端末内で読み込みます。ファイルはサーバーへ送信・保存せず、再読み込みすると失われます。

PPTXは静止スライドとして表示します。フォント・配置・アニメーション等の完全再現は保証しません。原本の見た目を揃える場合はPDFを利用してください。発表者ノートや台本をファイルから自動生成する機能はありません。[対応範囲と復旧手順](docs/slide-upload.md)

ファイルを選ばずに試す場合は3工程のサンプルを使えます。「自分の台本を編集」は任意の補助で、3工程のタイトル・本文を同じブラウザへ保存します。保存できない場合は画面だけに反映し、再読み込みで失われる旨を表示します。再編集は「発表を終了」→「はじめから」で準備へ戻ります。

**投影する:** 発表中に「スライドを全画面表示」。台本・設定・認識文字列・診断値を出さず、スライド全体を表示します。Escで元のページ・寄り道先・入力モードを保持して戻ります。全画面を利用できない場合は「スライドのみ表示」か通常画面で続けられます。[操作と検証](docs/projection-mode.md)

## カメラで使う

HTTPSの公開URLで「音声・カメラを設定」を開き、「同意してカメラを開始」を押してカメラの利用を許可します。準備画面で押すと発表も開始し、許可後にカメラ画像を取得します。自動撮影では、判定が終わってから約2秒待って次の静止画をOpenAIへ送ります。カメラ入力ではマイクを使いません。

1. 片手を開いて映します。判定が確定すると次の工程へ進み、判定・確信度・待ち時間を表示します。
2. 一度手を画面から下ろして「次の合図を出せます」を待ち、握り拳を映すと前へ戻ります。
3. 誤操作は「取り消し」で戻せます。「カメラを停止」でカメラ・送信を終了し、同じ発表中にカメラを再開できます。「発表を終了」は音声も含めて終了し、再開には「はじめから」での再準備が必要です。別タブへ移っても入力は停止します。

同じ手の保持・低確信度・古い返答・重複・無効な出力では動きません。通信失敗は停止し復旧方法を表示します。権限を拒否した場合は設定を確認して再開し、利用上限時は1分待ちます。

APIキーはサーバーの `OPENAI_API_KEY` だけに設定し、クライアントには渡しません。画像はこのアプリのログ・ファイルに保存しません。実装の接続は後述の表で追えます。

## 声で使う

「音声・カメラを設定」を開き、「同意して音声を開始」でマイクを許可し、「次へ」「前へ」「取り消し」「続きへ」などの操作語を1つずつ話します。ブラウザが確定した文字を定型句と照合し、対応する操作だけを実行します。途中の認識結果は表示だけです。「3枚目へ」と「確認」を分けて話すと、移動先の候補を確認して寄り道できます。音声での検索・開始・リセットは対象外です。

発話の「停止」は発表・音声・カメラを終了します。「音声を停止」ボタンは音声入力だけを止めます。認識は1コマンドごとに区切り、無音の間も次の操作を待ちます。無音による認識終了や `no-speech` では、短い待機を挟んで認識を再開します。発話開始（または最初の空でない途中結果）から6秒たっても確定しない場合は、その発話だけを破棄して次の操作を待ちます。権限・機器・通信エラーや、確定前に重なった発話で停止した場合は、開始ボタンを押し直してください。明示停止・発表終了・タブ離脱・カメラへの切り替え後は自動再開しません。

音声認識にはブラウザの機能を使い、このアプリのOpenAI APIキーは使いません。音声がブラウザ提供元の認識サービスへ送られる場合があります。非対応時はボタン・キーボードを使えます。詳しい仕様と検証結果は[音声の仕様と検証](docs/voice-input.md)にあります。

## まず試す流れ

1. PDFまたはPPTXを読み込み、先頭ページと枚数を確認して開始します。
2. 「次へ」または右矢印キーで進行します。最後のページでは、それ以上進みません。
3. ページ一覧で別ページを選び、「移動する」で寄り道します。確認前なら「キャンセル」で取りやめます。
4. 「続きへ戻る」で寄り道前のページへ戻ります。戻り先は1段、取り消しは直前の1操作です。
5. 「発表を終了」で入力も停止します。「はじめから」で再準備してから別のファイルを選べます。

発表中は主要操作・寄り道確認・復帰を画面下部の操作バーから使えます。入力状態と認識結果・エラー理由は発表画面に表示し、その場で再開または手動へ切り替えられます。詳細設定を閉じても発表状態は維持されます。

## ローカルで起動する

Node.js 24以降とnpmが必要です。
取得済みの場合は `npm ci` から実行してください。

```sh
git clone --branch main https://github.com/42libft/openai-devday-2026-community-hackathon-tokyo-team.git
cd openai-devday-2026-community-hackathon-tokyo-team
npm ci
npm run dev
```

`http://127.0.0.1:5173` を開きます。
ファイルの読み込みと手動操作はAPIキー・カメラ・マイクなしで使えます。カメラのAI判定を使うには、管理者が `.env.local` に `OPENAI_API_KEY` を設定してからサーバーを起動します。`.env.example` を参照してください。環境変数を `VITE_` で始めたり、キーをGitへ追加したりしないでください。Viteの開発・previewサーバーでも同じAPI処理を利用します。

## 操作と復旧の手順

| 操作 | 使い方・復旧 |
|---|---|
| 工程を前後へ動かす | 「次へ」「前へ」、左右矢印、PageDown / PageUp。最初・最後ではそれ以上進みません。 |
| 直前の操作を戻す | 「取り消し」、U。ページ移動など直前の1操作だけを取り消します。 |
| 寄り道する・戻る | ページ一覧 →「移動する」。候補をやめるなら「キャンセル」かEscape。復帰は「続きへ戻る」、R、または定型句「続きへ」。 |
| 止める・新しく始める | 「発表を終了」または発話の「停止」で発表・カメラ・音声を停止。「はじめから」→開始で新しい発表を準備します。「カメラを停止」と「音声を停止」はそれぞれの入力だけを止めます。 |

文字入力中・日本語変換中は工程のショートカットを抑止します。
候補提示後に状態が変わると、古い確認は適用しません。
カメラ・音声が使えない場合も、ボタンでページ移動・寄り道・復帰を使えます。

## 寄り道から戻す仕組み

寄り道の確定時に元のページを保存し、「続きへ戻る」で復元します。寄り道中に別のページへ進んでも、戻り先を上書きしません。入力にはイベントID・発表セッション・状態の版を付け、重複・古い状態・前の発表セッションから届いた操作を拒否します。ファイルを変更するとセッションも更新し、前の資料に対する操作を無効にします。

旧サンプルの検索・選択の状態復元は内部の回帰検証に残していますが、通常画面には架空資料の検索と文字コマンド入力を表示しません。

## Decisions APIを選んだ理由

カメラから受け取りたいのは「次へ・前へ・操作なし」の3択です。
`api/decide.js` は [Decisions API](https://developers.openai.com/api/docs/guides/decisions) の画像入力とchoice質問を使い、`gpt-6-luna` にこの3択を渡します。
confidenceと選択肢の確率がともに0.9以上の場合だけ操作候補を通し、曖昧な画像や不正出力では進みません。
実呼出しは `POST https://api.openai.com/v1/decisions` です。

## 連続操作を抑える仕組みの検証

同じ手を出し続けたときに何度も進まないよう、操作後は手を下ろした判定（確実なNONE）が来るまで次の操作を待ちます。
合成済みの5判定 `NEXT, NEXT, NONE, PREVIOUS, PREVIOUS` を本番の状態処理へ渡した再現テストでは、毎回実行する方式の4回に対し、本方式は2回だけ移動し、保持中の余分な移動を抑えました。

再現は `node scripts/gesture-comparison.mjs`。根拠は [比較結果JSON](docs/gesture-comparison.json) と [検証手順](docs/gesture-evidence.md) にあります。
この検証の対象は連続操作の抑止です。実画像での認識精度・API遅延・発表時間の短縮は未測定です。

## 適用範囲と制約

- PDF・PPTXは静止スライドの表示です。アニメーション・動画・PowerPointとの完全一致、発表者ノートの抽出は対象外です。
- 読み込んだファイルと発表の進行はこのタブ内だけに保持します。再読み込みで失われ、別端末・別タブへ同期しません。保存に成功したサンプル台本のタイトル・本文は同じブラウザに残ります。
- カメラの約2秒は判定後の待機間隔です。閾値0.9は認識精度90%を保証しません。精度や遅延は照明・背景・端末・回線にも依存します。
- レート制限はAPIインスタンス単位で、複数インスタンスを横断する厳密な課金上限ではありません。
- 実カメラ・実マイクの精度、現場での使いやすさ、時間短縮・負担軽減は未測定です。
