# 発表の相棒

**質問で寄り道しても、元の工程とデモの状態へ戻れる発表支援ツール。**
スライドと検索デモを行き来する発表者に向け、発表の工程・検索語・検索結果・選択中の資料をまとめて保存し、質問への対応後に復元します。

3工程の固定台本と架空の資料4件を使います。カメラの静止画を **Decisions API** に送り、開いた手は「次へ」、握り拳は「前へ」、手なし・不明は「何もしない」と判定します。ボタンとキーボードも同じ状態管理へ接続しています。

**実装状況（2026-10-18）：画像入力・実API呼出しコード・状態処理を接続済み。APIキー設定と実API・公開版の通し確認は作業中です。** 現在の公開URLは https://devday-presentation-companion.vercel.app/ ですが、追加機能が配備済みとはまだ扱いません。

## カメラで使う

HTTPSの公開URLとカメラ付き端末を使用します。「同意してカメラを開始」を押してブラウザで許可すると、発表が開始し、約2秒の間隔を空けて静止画をOpenAIへ送ります。マイクは使いません。

1. 片手を開いて映します。判定が確定すると次の工程へ進み、判定・確信度・待ち時間を表示します。
2. 一度手を画面から下ろして「次の合図を出せます」を待ち、握り拳を映すと前へ戻ります。
3. 誤操作は「取り消し」で戻せます。「停止」でカメラ・送信を終了します。別タブへ移っても停止します。

同じ手を保持しても連続移動しません。低確信度、古い状態への返答、重複、無効な出力は操作しません。通信失敗は停止して復旧方法を表示します。カメラ拒否時はブラウザの権限を変更して「同意して再開」、利用上限時は1分待って再開できます。手動ボタンはカメラなしで使えますが、カメラ認識の検証結果には含めません。

主導線は `src/main.js` → `src/input/camera.js` → `api/decide.js` → `src/state/presentation.js` → `src/ui/view.js` です。APIキーはサーバーの `OPENAI_API_KEY` のみに設定し、クライアントには渡しません。画像はこのアプリのログや保存ファイルに残しません。

## まず試す流れ

1. 「台本を確認して開始」を押し、「次へ」で2工程目「検索デモを見せる」へ進みます。
2. 「資料を探す」で **写真** を検索し、結果の **まちの色ギャラリー** を選びます。
3. 上部の3工程目「発表をまとめる」を押します。候補の確認が表示され、この時点では現在の工程は変わりません。
4. 「移動する」を押して寄り道します。寄り道先で **ノート** を検索し、**読書メモ** を選びます。
5. 「続きへ戻る」を押します。2工程目・検索語「写真」・検索結果「まちの色ギャラリー」・その選択が一緒に戻ります。

| 場面 | 工程 | 検索語 | 検索結果 | 選択中の資料 |
|---|---|---|---|---|
| 寄り道する前 | 検索デモを見せる | 写真 | まちの色ギャラリー | まちの色ギャラリー |
| 寄り道中に変更 | 発表をまとめる | ノート | チームのアイデア帳、読書メモ | 読書メモ |
| 続きへ戻った後 | 検索デモを見せる | 写真 | まちの色ギャラリー | まちの色ギャラリー |

復元は `test/state.test.mjs` で検証します。

手動の手順は [操作ガイド](docs/mvp-demo.md) を参照。

## ローカルで起動する

Node.js 24以降とnpmが必要です。
取得済みの場合は `npm ci` から実行してください。

```sh
git clone --branch work/mvp-presenter-20261018 https://github.com/42libft/openai-devday-2026-community-hackathon-tokyo-team.git
cd openai-devday-2026-community-hackathon-tokyo-team
npm ci
npm run dev
```

`http://127.0.0.1:5173` を開きます。
手動操作、検索と状態復元はAPIキーやカメラなしで使えます。カメラのAI判定には、管理者が `.env.local` に `OPENAI_API_KEY` を設定しサーバーを起動します。`.env.example` を参照してください。環境変数を `VITE_` で始めたり、キーをGitへ追加したりしないでください。Viteの開発・previewサーバーでも同じAPI処理を利用します。

## 操作と、困ったときの戻り方

| やりたいこと | 操作 | 結果・注意点 |
|---|---|---|
| 隣の工程へ進む・戻る | 「次へ」「前へ」、左右矢印、PageDown / PageUp | 工程だけを前後へ動かします。端ではそれ以上進みません。 |
| 直前の操作をやり直す | 「取り消し」、U | 進行・検索・選択など、直前の1操作を取り消します。連続して履歴を遡る機能ではありません。 |
| 別の工程へ寄り道する | 上部の工程を選ぶ → 「移動する」 | 確定時に、元の工程と検索・選択を保存します。 |
| 移動をやめる | 候補表示中に「キャンセル」、Escape | 移動候補を破棄します。 |
| 寄り道前の続きに戻る | 「続きへ戻る」、R、入力欄に「続きへ」 | 保存した工程・検索語・検索結果・選択をまとめて復元します。 |
| 資料を探す | 検索欄に語を入れて「検索」 | 架空の資料の名前・説明を部分一致で探します。空欄なら全4件を表示します。 |
| 検索結果がない | 別の語で再検索、または空欄で検索 | 画面に該当なしを表示します。検索直前に戻すなら「取り消し」を使えます。 |
| 入力した言葉が認識されない | 「次へ」「取り消し」「続きへ」「1枚目へ」などを入力 | 対応する定型句だけを受け付けます。未対応の文章は実行せず、画面に説明を表示します。 |
| 発表を止める・新しく始める | 「停止」→「はじめから」→開始 | 停止中は操作を進めません。「はじめから」で検索・選択もリセットします。 |

文字入力中や日本語の変換中は、キーボードのショートカットで工程を動かしません。
検索欄は120文字、操作の入力欄は180文字までです。
候補を提示した後に進行・検索などで状態が変わると、古い候補への確認は適用しません。

## 工程と検索を一緒に戻す仕組み

単に「前へ」で工程を戻しても、寄り道中に変えた検索語や選択は元に戻りません。
本アプリは寄り道の確定時に次の4項目をまとめて保存します。

```text
工程 + 検索語 + 検索結果IDの配列 + 選択中の資料ID
```

「続きへ戻る」はこの4項目を一度に復元します。
寄り道中の検索・選択・隣接工程への移動では戻り先を上書きしません。
保存できる戻り先は1段です。

入力にはイベントID、セッション番号、状態の版を付け、同じ入力の再送、古い状態への操作、前のセッションから届いた操作を状態処理で拒否します。
取消し用の履歴と寄り道の戻り先を分けることで、寄り道中の操作を取り消しても元の戻り先を保持します。

| 読みたい処理 | 実装・テスト |
|---|---|
| カメラ画像、送信同意、古い応答・連続合図の抑止 | `src/input/camera.js`、`src/ui/camera-panel.js`、`test/camera-input.test.mjs` |
| Decisionsの画像choice判定、入力・出力検証、失敗処理 | `api/decide.js`、`test/decisions-api.test.mjs` |
| カメラが実行できる操作の制限、停止・取消し後の拒否 | `test/camera-state.test.mjs` |
| 3工程、検索、寄り道、取消し、状態復元 | `src/state/presentation.js`、`test/state.test.mjs` |
| 定型句・キーボード入力とイベントの生成 | `src/input/manual.js`、`test/input.test.mjs` |
| 状態の一元管理と入力・画面の接続 | `src/controller.js`、`src/main.js`、`test/integration.test.mjs` |
| 移動の確認、検索結果、操作可能なボタン、状態・エラーの表示 | `src/ui/view.js` |

## DevDay新機能の利用状況

`api/decide.js` が `POST https://api.openai.com/v1/decisions` を呼び、`gpt-6-luna`へ画像と有限の選択肢を渡します。確信度と候補確率の両方を確認し、不明な画像で無理に移動しません。画像内の文章を操作指示として扱いません。実呼び出しのコードと、認証済み環境での実行成功は別であり、現在の確認状況は上表の通りです。[公式仕様](https://developers.openai.com/api/docs/guides/decisions)

## 適用範囲と制約

- カメラ画像は外部APIへ送信します。約2秒は判定後の待機間隔で、通信時間を加えた即応性は端末と回線に依存します。音声認識はありません。
- 0.9の確信度閾値は実装上の保守的な基準で、認識精度90%を保証する意味ではありません。照明、背景、手の遮蔽に影響されます。
- API側のレート制限はインスタンス単位です。複数インスタンスを横断する厳密な課金上限ではありません。
- 固定の3工程と架空の4資料を使ったデモです。任意のスライドやPowerPointの取込、台本生成はありません。
- 復元対象はこのタブ内の工程・検索・選択です。外部アプリや外部サービスの状態は復元しません。
- 戻り先は1段、取消しは直前の1操作です。複数段の寄り道や永続的な履歴はありません。
- ページを再読み込みすると状態は初期化されます。別端末・別タブへの同期や、終了後の復元はありません。
- 効果を確認できた範囲は、用意した入力から同じ状態へ戻れることです。実際の発表現場での効果や利用者テストは今後の検証事項です。
