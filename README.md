# 発表の相棒

手持ちのスライドで発表し、質問で寄り道した後に元のページへ戻れるツールです。PDF / PowerPoint（PPTX）を読み込み、一覧で確認してから開始します。ボタン・キーボードだけでも使えます。

[公開デモ](https://devday-presentation-companion.vercel.app/)（このブランチの配備は未実施）

## 読み込んで発表する

1. 「スライドを読み込む」でPDF / PPTXを選びます。25MB・1〜100ページに対応します。旧PPT・KEY・画像は直接読み込めません。
2. 一覧でページを選んで内容を確認します。「発表者ノート」は任意です。準備中に各ページへ最大4000文字を入力でき、自動生成はしません。
3. 「この資料で発表を開始」で1枚目から開始します。サンプル台本の入力・保存は不要です。
4. 質問への寄り道は一覧のページを選び「移動する」で確定します。「キャンセル」なら位置を維持し、「続きへ戻る」で寄り道前へ復帰します。戻り先は1か所です。
5. 「発表を終了」で音声・カメラも停止します。「はじめから」で同じ資料とノートを保持して再準備できます。別の資料は準備中に選択してください。

読み込み失敗・未対応形式・キャンセル・古い読込結果では、現在の資料を置き換えません。発表中のファイル選択は無効です。ページの描画に失敗した場合は「表示を再試行」か別ページへ移動できます。

## 対応形式・ノート・保存範囲

- PDFは同梱PDF.js、PPTXは同梱レンダラーで端末内に描画します。ファイルをサーバーやOpenAIへアップロードしません。保護PDF・破損ファイルには対応しません。
- PPTXは静止スライドです。配置・フォント・アニメーション等の完全再現は保証しません。原本の見た目を揃える場合はPDFを使ってください。
- 資料・任意ノート・発表位置・寄り道・取消し履歴はこのタブ内のメモリだけで保持し、再読み込み・タブを閉じると失われます。別端末との同期はありません。
- 旧版の固定3工程台本は通常画面から外しました。旧版がブラウザへ保存したデータは読み込みも上書きも削除もしません。
- 文字コマンド欄と架空資料検索は通常画面から外し、読み込んだ実資料の一覧で操作します。音声解析とキーボード操作は維持しています。

形式・失敗時の詳細とPR #31の検証記録は[読込ガイド](docs/slide-upload.md)を参照してください。

## 操作

| 操作 | ボタン・キー・声 |
|---|---|
| 前後に移動 | 前へ / 次へ、← / →、PageUp / PageDown。先頭・末尾ではそれ以上移動しません。 |
| 取消し | 取り消し、U。直前の移動を1回取り消します。 |
| 寄り道 | 一覧のページ → 移動する。声は「N枚目へ」→別発話で「確認」。実枚数の範囲だけ受け付けます。 |
| 候補をやめる | キャンセル、Escape、発話「キャンセル」。 |
| 元へ戻る | 続きへ戻る、R、発話「続きへ」。 |
| 発表を終了 | 発表を終了、Q、発話「停止」。音声とカメラも停止します。 |

ノートなどの文字入力中・日本語変換中はショートカットを抑止します。古い入力・重複入力・前の発表からの入力を拒否します。

## 声・手で使う

| 操作方法 | 必要なもの | 操作範囲 |
|---|---|---|
| 手動 | APIキー・カメラ・マイクは不要 | 読み込んだスライドの進行、寄り道・復帰・取消し |
| カメラ | カメラとサーバーのOpenAI APIキー設定 | 開いた手で次へ、握り拳で前へ |
| 音声 | マイクとブラウザの音声認識機能。OpenAI APIキーは不要 | 定型句で進行、寄り道・復帰・取消し・終了 |

詳しい設定を開き、各開始ボタンで同意したときだけ入力を開始します。カメラと音声は切り替えて使い、片方を開始すると他方が停止します。状態と「手動に切り替え」は常に確認できます。非対応・権限拒否時もボタンとキーボードで続けられます。

カメラは判定終了後に約2秒待って次の静止画をOpenAI Decisions APIへ送ります。音声は1コマンドごとに認識を区切り、エラー・予期しない終了・6秒の確定待ち超過では停止するため、開始ボタンで再開します。音声はブラウザ提供元の認識サービスへ送られる場合があります。このアプリは映像・音声を保存しません。「カメラを停止」「音声を停止」はそれぞれの入力だけを止めます。別タブへ移っても入力は止まり、自動再開しません。[音声の仕様](docs/voice-input.md)

## ローカルで起動する

Node.js 24以降とnpmが必要です。

```sh
git clone https://github.com/42libft/openai-devday-2026-community-hackathon-tokyo-team.git
cd openai-devday-2026-community-hackathon-tokyo-team
npm ci
npm run dev
```

`http://127.0.0.1:5173` を開きます。読込・手動操作・ノートはAPIキーなしで使えます。カメラ判定のサーバー設定は `.env.example` を参照してください。キーをクライアントやGitへ渡さないでください。

```sh
npm test
npm run preview
```

`npm test` はbuild・回帰・開発/配布出力のHTTP検査です。API試験は模擬fetchで実行します。ビルドは `dist/`、previewは通常 `http://127.0.0.1:4173` です。[公開設定](docs/static-output.md)

## Decisions APIを選んだ理由

カメラから受け取りたいのは「次へ・前へ・操作なし」の3択です。
`api/decide.js` は [Decisions API](https://developers.openai.com/api/docs/guides/decisions) の画像入力とchoice質問を使い、`gpt-6-luna` にこの3択を渡します。
confidenceと選択肢の確率がともに0.9以上の場合だけ操作候補を通し、曖昧な画像や不正出力では進みません。
実呼出しは `POST https://api.openai.com/v1/decisions` です。

## 連続操作を抑える仕組みの検証

同じ手を出し続けたときに何度も進まないよう、操作後は手を下ろした判定（確実なNONE）が来るまで次の操作を待ちます。
合成済みの5判定 `NEXT, NEXT, NONE, PREVIOUS, PREVIOUS` を本番の状態処理へ渡した再現テストでは、毎回実行する方式の4回に対し、本方式は2回だけ移動し、保持中の余分な移動を抑えました。

再現は `node scripts/gesture-comparison.mjs`。根拠は [比較結果JSON](docs/gesture-comparison.json) と [検証手順](docs/gesture-evidence.md) にあります。
この検証の対象は連続操作の抑止です。実画像での認識精度・API遅延・発表時間の短縮は未測定です。

## 制約

取消しは1操作、寄り道の戻り先は1か所です。実センサーの精度、発表現場での使いやすさ、時間短縮量は未測定です。レンダラーが対応するすべての資料・フォント・ブラウザの表示を保証するものではありません。
